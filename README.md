# Grow Flow — одностраничник с плавным чередованием фона

Кинематографичный hero-видео с логотипом → скролл-скраббинг сцены
«Знакомство» (кадр на весь экран, синий свет комнаты) → дальше обычный,
естественный поток: разделы идут один за другим, каждый плавно
"разворачивается" при входе в вьюпорт, а фон всей страницы мягко
перекрашивается между светлой и тёмной темой на границах разделов (без
резких скачков цвета) — приём в духе kookie-kollective.com. Чистый
HTML/CSS/JS, без фреймворков.

## Структура

```
index.html          — вся разметка (hero + разделы + модалка + outro + футер)
css/style.css        — стили, палитра в :root, локальные темы через [data-theme]
js/main.js           — вся логика: прелоадер, скраббинг «Знакомства», темы/reveal, формы, outro
assets/hero.mp4              — фоновое видео hero и outro
assets/logo-mark.png         — логотип в hero
assets/frames/sceneA/        — 24 кадра: подошёл, сел, положил руки на клавиатуру
assets/brand/                — доп. варианты логотипа
```

## Как это работает

### Фон и темы разделов
Один фиксированный слой `#bgLayer` (`position:fixed`, за контентом) —
единственное место, где хранится цвет фона всей страницы, с
`transition: background-color .8s`. Разделы сами прозрачны (кроме
«Знакомства» — там канвас) и объявляют локальную тему через атрибут
`data-theme="light"` или `data-theme="dark"` — CSS-правило `[data-theme]`
переопределяет `--bg/--fg/--fg-dim/--line/--accent` для всего поддерева.
`IntersectionObserver` в `js/main.js` (`rootMargin: '-50% 0px -50% 0px'`,
срабатывает на пересечении с серединой вьюпорта) следит, какой раздел
сейчас в фокусе, и переключает цвет `#bgLayer` на цвет его темы.

Чередование задано по разделам, а не по карточкам внутри них: Начало и
Знакомство — тёмные, Услуги — целиком светлый, Кейсы — целиком тёмный,
Контакты — светлые (см. атрибуты `data-theme` прямо в `index.html`).

**Важно:** `body` должен иметь `isolation:isolate` — без своей области
стека `z-index:-1` у `#bgLayer` проваливается за собственный canvas-фон
`html`/`body`, а не под секции (классическая ловушка с отрицательным
z-index).

Тема больше не определяется через `IntersectionObserver` с
`rootMargin` по центру вьюпорта — с высокой секцией (вся доска «Кейсы»
одним `[data-theme]`) это давало гонку: секция начинала считаться
"пересекающей центр" уже когда её верх едва зашёл за середину экрана,
то есть ещё до того, как предыдущая секция реально переставала быть по
центру, и если в одном кадре наблюдателя пересекались сразу две
секции — применялась тема той, что шла последней в DOM, а не той, что
реально видна. Сейчас на каждый тик скролла (`updateTheme` в
`js/main.js`) ищем секцию, чей верх выше центра вьюпорта, но ближе всех
к нему — детерминированно, без гонки между кадрами наблюдателя.

### Reveal-по-скроллу
Все карточки/блоки с атрибутом `data-reveal` получают класс `.is-visible`
от отдельного `IntersectionObserver`, когда попадают в вьюпорт (один раз,
дальше не трогаются) — плавное появление (`opacity`+`translateY`), а у
гигантского слова услуги — ещё и `clip-path`-разворот сверху вниз.

Карточки услуг (`.service-block`) — особый случай: у них свой
`serviceRevealObserver`, который не отписывается после первого
срабатывания, а просто переключает `.is-visible` по `entry.isIntersecting`
в обе стороны — карточка плавно появляется при скролле вниз и точно так
же плавно скрывается при скролле вверх.

- **Hero** — фоновое видео (`HERO_VIDEO_URL`) с логотипом; при скролле
  плавно гаснет и увеличивается.
- **Знакомство** (`#sceneA`, тёмная тема + локальный синий `--accent`) —
  единственная оставшаяся pinned-сцена на сайте: `position:sticky`
  канвас высотой в весь экран, кадр рисуется с обрезкой по типу
  `object-fit: cover` (`makeCoverScrubber` в `js/main.js`) — без чёрных
  полос по бокам, цвета кадров — оригинальные, без цветокоррекции.
  Скролл проигрывает кадры «подошёл → сел → положил руки на клавиатуру»;
  на последнем кадре движение останавливается и держится до конца пина,
  дальше секция заканчивается. Текстовая карточка появляется, когда руки
  уже почти на клавиатуре (`p >= 0.82`).

  Исходный ролик (референсная съёмка) на середине сам переключает свет в
  комнате по цветам (синий → красный → зелёный → жёлтый → снова синий) —
  это часть исходника, а не наша цветокоррекция. Раз нужен только синий
  свет, кадры этого куска (было 40, стало 24) просто вырезаны из
  секвенции: оставлены только `подошёл → сел` (кадры с исходно синим
  светом) и `руки на клавиатуре` (тоже исходно синий свет), склеены
  напрямую. У склейки — `hardCuts: [13]` в опциях `makeCoverScrubber`:
  на этом стыке кадры не соседние по-настоящему, обычный кроссфейд-блендинг
  между ними давал двойную экспозицию (видно руки сразу в двух позах) —
  вместо этого на стыке жёсткая склейка по середине шага без альфа-блендинга.
- **Услуги** (`#sceneB`) — четыре карточки одна под другой (SMM → Таргет
  → SEO → Продакшн) на светлом фоне. Слева — тонкий вкладочный рейл
  (`position:sticky`, `align-self:start` обязателен — иначе грид
  растягивает рейл на всю колонку и его sticky-контейнер съезжает),
  активная вкладка получает скобки `[ ]` через CSS. Клик по вкладке
  скроллит к нужной карточке (`scrollIntoView`), клавиши 1–4 и кнопка
  «Подробнее о составе работ» открывают модалку с полным списком.
  Справа на каждой карточке — честно подписанный плейсхолдер
  `.service-object` вместо предметной съёмки.
- **Кейсы** (`#work`, тёмная тема) — доска работ по образцу секции WORK
  на kookie-kollective.com: гигантская фоновая надпись «НАШИ РАБОТЫ»,
  разномастные карточки внахлёст (не сетка — у референса это выглядит
  как рассыпанные на столе фотографии, у нас `.case-card` абсолютно
  спозиционированы по `top`/`left`/`width` в процентах, у каждой свой
  z-index для нахлёста), параллакс-дрейф на скролле (`data-speed` на
  каждой карточке — `measureCaseCards`/`updateCasesParallax` в
  `js/main.js`). Картинки карточек — плейсхолдер-градиенты с инициалом;
  заменить на реальные превью кейсов.
- **Контакты** (`#sceneC`, светлая тема) — форма + **концепт-мокап
  телефона**: живой текст, синхронный вводу в полях, с курсором и
  пульсацией на каждое нажатие. У самого мокапа (экран, текст, чехол) —
  фиксированные тёмные цвета, не завязанные на тему раздела: телефон
  всегда выглядит как телефон, независимо от того, светлая сейчас
  секция или тёмная. Помечен тегом «Концепт · заменить на съёмку»;
  появляется вместе с reveal-блоком секции.
- **Outro** («финал») — во весь экран надпись «GROW FLOW», внутри букв
  которой играет видео (canvas + `globalCompositeOperation:
  'destination-in'`). Рисуется только пока секция видна во вьюпорте.
  Если видео не загрузится — плейн-текстовый фолбэк.
- **Футер** — статичное эхо той же надписи «GROW FLOW» крупным кеглем
  над копирайтом.
- **Индикатор прогресса** справа — вертикальная шкала с метками текущего
  раздела по всей странице (не связан с системой тем).

## Плейсхолдер-материалы, которые нужно заменить

1. Кадры «Знакомства» — референсная съёмка для обкатки механики (в
   кадрах видны чужие вшитые субтитры, а исходный ролик ещё и сам
   переключает цвет света в комнате — см. выше). Переснять под свой
   сюжет одним ровным дублем при постоянном свете и экспортировать как
   `f_001.jpg … f_0NN.jpg`; число кадров меняется в
   `SCENES_META.sceneA.frames`, склейку `hardCuts` в вызове
   `makeCoverScrubber` можно убрать, если пересъёмка будет одним куском.
2. Карточка `.service-object` в каждом блоке услуги — плейсхолдер вместо
   предметной съёмки. Когда появится фото — заменить на `<img>` того же
   размера, идле-анимация (`serviceObjectFloat`) уже есть в CSS.
3. Карточки `.case-card-media` в кейсах — градиент-плейсхолдеры с
   инициалом вместо реальных превью проектов; заменить на `<img>`/видео
   того же аспект-рейшо (задан на `.case-card-media` через `nth-child`),
   параллакс уже привязан к `data-speed`.
4. Телефон-мокап в контактах (`.phone-mock`) — можно продолжать
   использовать как есть (не привязан к конкретному видео, только к
   полям формы), либо заменить на реальную съёмку телефона в руке.
5. Hero и outro-видео — `assets/hero.mp4` (`HERO_VIDEO_URL` и
   `OUTRO_VIDEO_URL` в `js/main.js`, можно указать разные файлы).

## Адаптивность

На экранах уже 820px индикатор прогресса, вкладочный рейл услуг и
предметные карточки-плейсхолдеры скрываются, карточки услуг и кейсы
встают в одну колонку (абсолютное позиционирование кейсов отключается —
`position:static`, без нахлёста и параллакса), панель контактов
растягивается на всю ширину. Анимации уважают `prefers-reduced-motion`;
параллакс кейсов также отключается на тач-устройствах (`pointer: coarse`).
